uni-skybox 基准采集页

先把 npm run build 和 node scripts/gen-assets.mjs 跑完，再从 npm run bench 打开本页。每一项的结果都有对应按钮导出，表号与论文正文一致。

0 · 环境信息（表 1）

GPU 型号取自 WEBGL_debug_renderer_info，被浏览器屏蔽时显示 «隐藏»，此时以系统信息为准。

1 · 冷启动至首帧（表 3）

第 1 次含贴图下载与解码，第 2 次起为纹理上传；两组分开报告，不要混在一起求平均。 本地服务对贴图发了 no-store，所以每次试验都是真实下载——这是偏保守的测法，生产环境命中缓存时数字会更低。

2 · 稳态帧间隔与单帧耗时（表 4）

帧间隔由 requestAnimationFrame 决定，距 16.7 ms 越远说明掉帧；单帧耗时分开记 «仅提交» 与 «含 readPixels 同步»，后者才把 GPU 光栅化等待算进来。 不用 gl.finish() 是因为在 ANGLE / D3D11 后端上它实测并不阻塞，读数恒为 0。

3 · 多实例显存占用（表 5、图 6）

所有实例落在同一个 canvas 上，因此共用同一个 WebGL 上下文——纹理对象不能跨上下文共享，这是 WebGL 的硬约束。 显存按 6 × 边长² × 4 字节估算，浏览器不提供读取接口。

4 · 上下文丢失至画面恢复（表 6）

两组都用 WEBGL_lose_context 强制丢失；「复用」组靠资源池保留已解码图像，「重载」组先清池再重新请求。

5 · 能力自检（表 7 的单机部分）

表 7 的通过率需要多机型实跑：H5 在 Chrome / Safari / 微信内置浏览器，小程序在 iOS 与 Android 各取主流机型。
